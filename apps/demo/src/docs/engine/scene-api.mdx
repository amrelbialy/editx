# Scene API

The `engine.scene` API manages scene creation, pages, layout, and legacy scene serialization.
Use [Document API](/docs/engine/document-api) for new native project persistence.

## Creating a Scene

```ts
await engine.scene.create({ width: 1920, height: 1080 });
```

This creates a scene block, a first page, and sets up the renderer. History is cleared after creation so it isn't undoable.

## Active Scene & Page

```ts
engine.scene.getScene();       // number | null
engine.scene.getCurrentPage(); // number | null
engine.scene.getPages();       // number[]
engine.scene.setActivePage(pageId);
```

Page activation is synchronous and does not create, clear, or merge undo/redo entries.
The target must exist, have type `"page"`, and be a direct child of the active scene.
Invalid targets throw `ActivePageError` with `pageId` and one of these `code` values:

| Code | Meaning |
|------|---------|
| `PAGE_NOT_FOUND` | The block ID does not exist. |
| `BLOCK_NOT_PAGE` | The block exists but is not a page. |
| `PAGE_NOT_IN_ACTIVE_SCENE` | The page is detached, nested, belongs to another scene, or no scene is active. |

Invalid activation leaves navigation and history unchanged. Re-selecting the current page is a
no-op. The engine-level `engine.setActivePage(pageId)` follows the same contract.

### Active-page subscription

```ts
import type { ActivePageChangedEvent } from "@editx/engine";

const unsubscribePage = engine.scene.onActivePageChanged(
  ({ pageId, previousPageId }: ActivePageChangedEvent) => {
    // Update host navigation; either ID can be null for an empty scene.
  },
);

// engine.onActivePageChanged(callback) is an equivalent subscription.
unsubscribePage();
```

Outside a command batch, notifications are synchronous, once per effective page-ID change, and
work without a renderer. Inside a batch, page and selection notifications wait until the outer
batch ends and history is settled; only the final net page change is published.
Creating or loading a scene publishes only its final navigation transition; notifications do not
mean rendering has finished. Await `create()` or `loadFromString()` for scene setup completion.
Subscriptions are separate from block lifecycle events and are not sent through `event.subscribe`.

## Page Management

```ts
const pageId = engine.scene.addPage({ width: 1080, height: 1080 });
const duplicateId = engine.scene.duplicatePage(pageId);
engine.scene.movePage(duplicateId, 0);
engine.scene.removePage(pageId); // throws if last page
```

Adding a page activates it. Removing the active page selects the first remaining page in scene
child order and emits one active-page notification. Removing another page leaves navigation
unchanged and emits none. Unknown or foreign page IDs are rejected before removal.

`duplicatePage(pageId)` returns a fresh page ID, inserts the copy immediately after its source,
and activates it. The source must be a direct page of the active scene, matching both its parent
reference and the scene child list. Its name, kind, dimensions, background, positions, grouped
content, text formatting, crops, shapes, fills, and effects are preserved without a position offset
or name suffix. Every copied block and sub-block gets a fresh ID; internal links are remapped,
mutable state is independent, and external resource strings are retained. Duplication does not
automatically change block selection or group context.

Creation, dimensions, attachment, and activation form one undo entry. Removal, subtree destruction,
and fallback activation also form one entry. Duplication and its activation are likewise one entry.
Undo/redo restores the same page IDs, complete content
(including nested groups, fills, shapes, and effects), dimensions, and page order. These APIs
participate in an existing outer command batch without adding separate history entries.
Silent-scoped commands remain outside history even when their silent scope ends before the
outer batch does. Rendering and lifecycle delivery settle before host selection, page, and
history callbacks; reentrant changes do not publish stale pending page transitions.

Creation, duplication, and active-page removal record their navigation transition. Undo restores the previous
active page; redo restores the created/duplicated page or removal fallback, even if the host navigated
elsewhere in between. Removing a non-active page does not record navigation, so undo/redo preserves
later page switches. Plain page navigation never creates an undo entry.

Page width and height must be finite positive numbers. Invalid dimensions, missing scenes, unknown
page IDs, and attempts to remove the final page throw before changing document state or history.
Invalid duplication targets or missing/cyclic subtree references also throw before allocating
copy IDs or changing the document, selection, history, or pending redo.

Direct block commands still reconcile stale navigation to the first remaining page, or `null` if
none remain. When a batch also destroys a recorded navigation target, replay falls back to the
first remaining page in the recorded scene rather than activating an invalid page.

### Reordering pages

`movePage(pageId, index)` moves a direct page of the active scene to its final zero-based
position among pages. Finite integer indices are clamped to the first/last page; fractional,
`NaN`, and infinite indices throw `RangeError`. Unknown, nested, detached, foreign, or non-page
targets throw before changing state or history. Both the parent reference and scene child-list
membership must match.

Reordering changes only the scene child order. Non-page scene children retain their exact slots;
page content, active page, block selection, and camera stay unchanged. One undo step restores
the old order, and redo restores the new order without overwriting subsequent valid page navigation.
Moving to the current effective index is a strict no-op: no history entry, lost redo, event, or render.

### Page-order subscription

```ts
import type { PageOrderChangedEvent } from "@editx/engine";

const unsubscribeOrder = engine.scene.onPageOrderChanged(
  ({ sceneId, pageIds, previousPageIds }: PageOrderChangedEvent) => {
    // Update the page strip from the new ordered page IDs.
  },
);

// engine.onPageOrderChanged(callback) is equivalent.
unsubscribeOrder();
```

The event reports any effective change to the active scene's page sequence or scene identity,
including add, remove, duplicate, reorder, undo/redo, creation, loading, and switching scenes.
It does not fire initially, for page activation alone, or for content-only edits. Read `getPages()`
to seed a page strip before subscribing.

`sceneId` is the current scene, or `null` after clearing navigation. `previousPageIds` is the
previously published active-scene sequence and may belong to another scene after a switch.
The payload and both arrays are frozen, read-only snapshots, not live store arrays.

Command notifications follow rendering/lifecycle delivery and settled history. An outer batch
publishes only its final net change; restoring the prior sequence emits nothing. Silent commands
remain observable without becoming undoable. Pending events are derived from current state at
delivery, so reentrant mutations do not publish stale queued orders. Notifications work without
a renderer. As with active-page events, await `create()` or `loadFromString()` for scene setup completion.

## Page Properties

```ts
import type { PageMetadata, PageProperties, PagePropertiesUpdate } from "@editx/engine";

const pageId = engine.scene.getCurrentPage()!;
const update: PagePropertiesUpdate = {
  name: "Front cover",
  width: 1200,
  height: 1600,
  backgroundColor: { r: 1, g: 0.98, b: 0.94, a: 1 },
  metadata: { thumbnailAlt: "Front cover preview", uiGroup: "Covers" },
};
engine.scene.setPageProperties(pageId, update);
const page: PageProperties = engine.scene.getPageProperties(pageId);
engine.scene.resizePage(pageId, 1080, 1350);
```

These APIs require a direct page of the active scene, matching both its parent reference and
scene child-list membership. They can edit a background page without activating it. Missing,
foreign, detached, nested, and non-page targets throw before mutation.

An update can change any combination of name, dimensions, background color, and metadata.
Width and height must be supplied together and must be finite positive numbers; fractional
sizes are preserved. Names are preserved exactly, including whitespace and empty strings.
Background colors use normalized RGBA channels, each finite and in `[0, 1]`; invalid values
are rejected, not clamped. Getters return defensive color and metadata snapshots.

`PageMetadata` is a read-only map of string keys to string values for optional UI hints,
such as thumbnail alternative text or grouping labels. It is not thumbnail image data,
an asset catalog, export settings, or document/template metadata. Omit `metadata` to retain
it, pass an object to replace the complete map, or pass `null` to remove it. An empty map
`{}` is distinct from absent metadata, which getters return as `null`.

Each effective update is one atomic command, one undo step, and one page `updated`
lifecycle event. Existing outer batches coalesce updates; silent scopes stay outside history.
Use `engine.event.subscribe([pageId], callback)` for property changes; they do not emit
active-page or page-order notifications. Validation happens before any mutation.
Same-value updates, including metadata with the same key/value pairs in a different key order,
are strict no-ops: no lost redo, history entry, notification, or render.

Resizing changes **page bounds only**. Descendant positions, sizes, formatting, and crops are
unchanged, even when they fall outside the smaller bounds. Page navigation, block selection,
camera, scene layout, other pages, and new-page defaults are unchanged. Undo/redo restores
all updated properties together without overriding later valid navigation. Names, mixed
dimensions, background colors, and metadata survive native save/load and page duplication.

Use `engine.exportPage(pageId, options)` to export any direct page without activating it.
It uses that page's authored dimensions and owned artwork, clipped to its bounds, and
does not change navigation, selection, camera, visibility, or history. See
[page-targeted export](/docs/engine/engine-api#export-a-page-by-id) for formats,
resource readiness, and identified failures. Legacy `exportScene` behavior is unchanged.

The existing `engine.block.getName/setName`, `getPageDimensions/setPageDimensions`, and
`getPageFillColor/setPageFillColor` remain available. `block.setPageDimensions` now uses the
same atomic bounds-only resize command and requires a direct page of the active scene;
invalid targets or dimensions throw rather than partially updating state.

### Try the page APIs

The [multi-page SDK playground](/playground/pages) seeds three pages with different dimensions,
colors, and grouped artwork. It provides page controls, atomic property edits, undo/redo,
native snapshot save/load, downloadable JSON, and live SDK state/events.

This is an opt-in diagnostic lab, not the finished multi-page editor UI. Pages currently
share the same canvas origin. Backgrounds follow document order, but artwork from different
pages overlaps. Activating a page changes SDK navigation but does not isolate its canvas view.
"Bring active to front" performs an explicit, undoable reorder, not a preview filter, and
does not change authored visibility. The built-in zoom badge can lag programmatic fits;
the live SDK state reports the actual zoom. Page-targeted export and the production page
strip are separate roadmap steps.

## Default Page Dimensions

```ts
engine.scene.setDefaultPageDimensions(1920, 1080);
engine.scene.getDefaultPageDimensions(); // { width, height }
```

Defaults must be finite positive dimensions. They apply only to subsequently added pages,
not existing pages. Changing layout, aspect-ratio lock, zoom, or the current page does not
rewrite authored page dimensions.

## Aspect Ratio Lock


## Legacy scene serialization

These deprecated codecs retain compatibility with existing scene files:

```ts
const json = engine.scene.saveToString();
await engine.scene.loadFromString(json);
```

`saveToString()` emits scene format version `2`. Version 2 persists groups, SVG
paths, gradient and image fills, text curves, rich run styles, and text background
geometry. `loadFromString()` accepts versions `1` and `2`; an explicit forward-only
pipeline advances v1 through v2, then converts legacy content to the current native
representation. Missing feature fields keep their established getter/renderer
fallbacks without being inserted. Other versions throw an
`Unsupported scene version` error.

Loading rebuilds the block hierarchy and renderer state, then clears history so
the restored document starts with a clean undo stack.

The complete block graph, property shapes, and active scene/page references are validated
before migration or replacing live blocks. Invalid input rejects with `DocumentValidationError`
without changing document, history, editing state, or rendering. Malformed JSON remains
a `SyntaxError`. A scene with a `null` active
page selects its first direct page, if any; loading an empty document clears stale navigation.
Missing feature properties retain their existing getter/renderer fallbacks rather than
being populated during validation. See [Document API](/docs/engine/document-api)
for issue codes, paths, and compatibility rules.

Each legacy load assigns a fresh document ID and empty document metadata.
For new saves, `engine.document.saveToString()` writes a versioned envelope without
active-page navigation; `engine.document.loadFromString()` reads that envelope
and these legacy scenes. The legacy scene loader does not read envelopes.
Successful loading clears history. Renderer/setup failures may reject after live
state has changed; loading does not yet guarantee asynchronous rollback.

## Event API

Subscribe to block lifecycle events:

```ts
// Subscribe to specific blocks
const unsubscribeBlock = engine.event.subscribe([blockId], (events) => {
  for (const e of events) {
    console.log(e.type, e.block); // "created" | "updated" | "destroyed"
  }
});

// Subscribe to ALL block events
const unsubscribeAll = engine.event.subscribe([], (events) => {
  // ...
});

// Unsubscribe
unsubscribeBlock();
unsubscribeAll();
```

With a renderer attached, events are deduplicated and delivered at the end of
each engine update cycle. A rendererless engine currently queues lifecycle events
without automatically flushing them.
