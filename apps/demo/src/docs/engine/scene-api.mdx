# Scene API

The `engine.scene` API manages scene creation, pages, layout, and serialization.

## Creating a Scene

```ts
await engine.scene.create({ width: 1920, height: 1080 });
```

This creates a scene block, a first page, and sets up the renderer. History is cleared after creation so it isn't undoable.

## Active Scene & Page

```ts
engine.scene.getScene();       // number | null
engine.scene.getCurrentPage(); // number | null
engine.scene.getPages();       // number[]
engine.scene.setActivePage(pageId);
```

Page activation is synchronous and does not create, clear, or merge undo/redo entries.
The target must exist, have type `"page"`, and be a direct child of the active scene.
Invalid targets throw `ActivePageError` with `pageId` and one of these `code` values:

| Code | Meaning |
|------|---------|
| `PAGE_NOT_FOUND` | The block ID does not exist. |
| `BLOCK_NOT_PAGE` | The block exists but is not a page. |
| `PAGE_NOT_IN_ACTIVE_SCENE` | The page is detached, nested, belongs to another scene, or no scene is active. |

Invalid activation leaves navigation and history unchanged. Re-selecting the current page is a
no-op. The engine-level `engine.setActivePage(pageId)` follows the same contract.

### Active-page subscription

```ts
import type { ActivePageChangedEvent } from "@editx/engine";

const unsubscribePage = engine.scene.onActivePageChanged(
  ({ pageId, previousPageId }: ActivePageChangedEvent) => {
    // Update host navigation; either ID can be null for an empty scene.
  },
);

// engine.onActivePageChanged(callback) is an equivalent subscription.
unsubscribePage();
```

Outside a command batch, notifications are synchronous, once per effective page-ID change, and
work without a renderer. Inside a batch, page and selection notifications wait until the outer
batch ends and history is settled; only the final net page change is published.
Creating or loading a scene publishes only its final navigation transition; notifications do not
mean rendering has finished. Await `create()` or `loadFromString()` for scene setup completion.
Subscriptions are separate from block lifecycle events and are not sent through `event.subscribe`.

## Page Management

```ts
const pageId = engine.scene.addPage({ width: 1080, height: 1080 });
engine.scene.removePage(pageId); // throws if last page
```

Adding a page activates it. Removing the active page selects the first remaining page in scene
child order and emits one active-page notification. Removing another page leaves navigation
unchanged and emits none. Unknown or foreign page IDs are rejected before removal.

Creation, dimensions, attachment, and activation form one undo entry. Removal, subtree destruction,
and fallback activation also form one entry. Undo/redo restores the same page IDs, complete content
(including nested groups, fills, shapes, and effects), dimensions, and page order. Both APIs
participate in an existing outer command batch without adding separate history entries.
Silent-scoped commands remain outside history even when their silent scope ends before the
outer batch does. Rendering and lifecycle delivery settle before host selection, page, and
history callbacks; reentrant changes do not publish stale pending page transitions.

Creation and active-page removal record their navigation transition. Undo restores the previous
active page; redo restores the created page or removal fallback, even if the host navigated
elsewhere in between. Removing a non-active page does not record navigation, so undo/redo preserves
later page switches. Plain page navigation never creates an undo entry.

Page width and height must be finite positive numbers. Invalid dimensions, missing scenes, unknown
page IDs, and attempts to remove the final page throw before changing document state or history.

Direct block commands still reconcile stale navigation to the first remaining page, or `null` if
none remain. When a batch also destroys a recorded navigation target, replay falls back to the
first remaining page in the recorded scene rather than activating an invalid page.

## Page Dimensions

```ts
engine.scene.setDefaultPageDimensions(1920, 1080);
engine.scene.getDefaultPageDimensions(); // { width, height }
```

```ts

```


## Serialization

Save and restore the entire scene:

```ts
const json = engine.scene.saveToString();
await engine.scene.loadFromString(json);
```

`saveToString()` emits scene format version `2`. Version 2 persists groups, SVG
paths, gradient and image fills, text curves, rich run styles, and text background
geometry. `loadFromString()` accepts versions `1` and `2`; version 1 documents
use feature defaults for fields that did not exist yet. Other versions throw an
`Unsupported scene version` error.

Loading rebuilds the block hierarchy and renderer state, then clears history so
the restored document starts with a clean undo stack.

Active scene/page references are validated before replacing live blocks. Invalid references
reject loading without changing the current document or history. A scene with a `null` active
page selects its first direct page, if any; loading an empty document clears stale navigation.
This is navigation validation, not full document-schema validation.

## Event API

Subscribe to block lifecycle events:

```ts
// Subscribe to specific blocks
const unsubscribeBlock = engine.event.subscribe([blockId], (events) => {
  for (const e of events) {
    console.log(e.type, e.block); // "created" | "updated" | "destroyed"
  }
});

// Subscribe to ALL block events
const unsubscribeAll = engine.event.subscribe([], (events) => {
  // ...
});

// Unsubscribe
unsubscribeBlock();
unsubscribeAll();
```

With a renderer attached, events are deduplicated and delivered at the end of
each engine update cycle. A rendererless engine currently queues lifecycle events
without automatically flushing them.
